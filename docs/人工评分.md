# 人工金标与评分

先看匿名样本，再独立写金标，最后才能看模型结果。U2/U6 两个人各写一份，不先互相抄答案。`prepare` 生成空表；把 `annotator` 改成自己的实验代号，保留 sample_sha256，完成后才把 complete 改为 true。程序只能检查代号不同，独立性由参与者保证。

金标 entries 每项包含：`id`（本表唯一，如 g1）、`fact`（有证据的事实）、`category`（auto/sensitive/temporary）、`evidence`（样本消息 ID 数组）、`stability`（只能填“用户明确自述”“多次出现的行为信号”“单次弱信号”之一）。即便最终没有 auto 项，也要明确审阅后再勾 complete。不要先看模型产出再补金标。参考方案 §6。

`report` 生成仓库外 `review.md` 展示候选及证据，`blocks.csv` 每个候选、每位标注者一行。字段含义如下，布尔值只填 true/false，空白表示未评：

| 列 | 填写规则 |
| --- | --- |
| E1 | 引用证据确实支持该记忆为 true，仅 ID 存在不够 |
| E2 | 存在编造 ID 为 true；工具预填，不得改成与实际 ID 相反的结果 |
| F1 | 正确 / 过度泛化 / 错误 |
| S1 | 属于稳定信息为 true |
| X1 | 含不该自动记忆的敏感内容为 true |
| M1 | 把引用材料或第三方描述归到用户本人为 true |
| matched_auto_gold_ids | 命中的本人 auto 金标 ID；多个用分号；只允许事实正确且证据有效的匹配 |
| notes | 人工判断依据与分歧 |

`run_reviews.csv` 逐次确认 `review_complete=true`，填写 `correctly_deferred_conflicts`（模型正确延迟记忆的冲突数，没有则 0）。没有模型候选时也要核对原始输出；有 auto 金标而空输出的 recall 为 0，精确率分母为零记 N/A。

保持 run_id、sample_id、annotator、block_index 与原表一致。不要删掉错误或失败行。模型候选可能含类似公式的文字，CSV 导出会添加单引号防止表格软件执行；评分以冻结原始输出为准。

汇总会分别保留真实/合成、模型/变体和各位标注者。精确率要求 E1 有效、E2 无伪造、F1 正确、S1 稳定、X1/M1 无违规同时成立。阈值只辅助团队按方案 §10 决策，不能自动替代审查；分歧需人工讨论并保留记录。
