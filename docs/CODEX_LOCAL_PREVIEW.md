# Codex 本地聊天预实验

用户允许读取和使用本人在本机的 Codex 聊天。本工具先把这些记录整理为可核对的输入，**只在本地处理，不把它们直接发送给模型服务**。原始日志只读，输出放仓库外。

## 执行与产物

在项目根目录执行，使用新的输出目录，固定结束时刻以便复核：

```powershell
.\scripts\spike.ps1 codex -roots 'C:\Users\LiangYS\.codex\sessions;C:\Users\LiangYS\.codex\archived_sessions' -local-consent -now 2026-10-13T14:42:22Z -out D:\app\MemorySpike\private\codex-preview-20261013-v2
```

该路径已用于本次输出，复跑请使用新的目录。命令不读取图片、附件、SQLite、其他应用的数据或账号凭据。不启动子代理。允许的 roots 必须由本人明确指定；已知新格式之外的日志采取保守排除，不猜测为真人消息。

| 文件 | 用途 |
| --- | --- |
| preview.json | C1 单人输入、摘要、来源、权限状态和取样统计 |
| sample-review.md | 逐条编号的文字，供本人检查隐私和取样准确性；原文用代码缩进显示，不自动加载链接或图片 |
| collection-summary.json | 排除/去重/脱敏等计数及局限，不含消息正文 |
| gold.blank.json | 独立人工金标空表，complete=false；没有代理预填的答案 |

`local_processing_consent=true` 仅表示允许本地处理。`model_transmission_consent=false`、`formal_experiment_eligible=false` 保持为 false。C1 也不能通过现有正式六样本 runner 的校验，不能改名成 U1/U2/U3/U6 来隐藏来源差异。

## 筛选和复核规则

1. 枚举显式根目录中近期修改的 JSONL，以文件打开时的大小读取快照；单文件最多 128 MiB、单行最多 64 MiB、最多 3000 个文件。修改日期只用于减少候选读取，消息日期依据自己的 create_time，不用日志重存时间。
2. session_meta 必须明确标为 user 线程，来源为正常客户端字符串；排除子代理、guardian 和无法确认来源的线程。要求 task_started 有本人发起的 composer/edit_user_message/remote_ios，并且没有上游代理或父 turn。
3. 只接受 `role=user`、`type=message`，同时具有消息 ID、turn ID、原始 create_time 和一一对应的 `content_item_kinds`。只保留 `user.text`，过滤环境/页面/AGENTS/图片包装。附件声明只留下 `My request` 后的请求文字；工具问答包装暂保守排除。
4. 先按消息 ID 去重；同一 ID 的正文或时间冲突则排除。不同 ID 但原始时间与正文相同也视为副本；不同时间的重复输入保留，不擅自把它们视为伪造。客户端若同时改写时间和 ID，仍可能无法识别副本。
5. 在字符截断前遮盖常见 API Key、JWT、显式密码、带密码的连接串、邮箱、手机号、证件号、IPv4 和 Windows 用户目录名。这不等于完整脱敏，姓名、自由文本住址、健康或第三方信息必须人工检查。
6. 按最近用户消息选最多 50 个会话；每会话先取 15 条，再按最近优先补足，最多 500 条、单条 2000 字符、总量约 24k token。只复用原方案的配额与匿名编号函数，不伪造学校 `source=web`、Project 或分支元数据。

现有日志的来源标记并不覆盖所有历史。统计里的“无法确认”不能直接解释成代理消息，“文件排除数量”也不等于用户数量。正式质量评估不能把这份经过严格来源筛选的数据当作完整 30 天历史。

## 本次准备结果（2026-10-13）

本地实际处理 509 个近期文件，其中 152 个符合明确的用户线程来源，353 个不是可确认的用户线程，4 个超过文件大小限制。最终得到 **18 个会话、108 条本人文字，近似 3943.5 token**。v2 自动遮盖 3 条消息中的 3 处片段。时间窗虽然设为最近 30 天，但保留下来的消息实际只覆盖 10 月 10 日至 13 日；不能描述为完整一个月的数据。

没有模型调用，尚无抽取质量分数。此前 v1 私人预览保留供核对；v2 增加内部 IP 和本机用户目录名遮盖，两份均不得上传 Git。

24 项测试及 go vet 通过，其中新增 9 项覆盖真实输入来源、原始消息日期、自动包装排除、设备信息/凭据遮盖、复制去重、冲突 ID、损坏日志、本地授权和 C1 与正式矩阵隔离。生成后的 v2 样本未检出常见 Key 和 IPv4 格式；这不是全面隐私审查结论。
