# 本地标注页面

## 给标注者

打开 `http://127.0.0.1:8787`，每次只处理一段自己说过的话。普通提问点“不用记住”；有个人信息则选择长期、临时或敏感，划选原句后点“添加选中的原话”，再选择判断依据。原句可以改成更准确的一句话，一段话里有多个事实可以分别添加。拿不准的先留着，最后点“去未完成的题目”回顾。

“保存进度”和“保存，下一条”都会写入本机文件。关闭页面前先保存；只选择而没有点保存的修改仍在页面内，离开时会有提示。进度条表示当前填写数量，底部保存时间才表示已写入磁盘。刷新可恢复上次保存的题号和内容。

全部检查后，点“完成并保存标注”。遗漏题目、拿不准、事实为空或没有判断依据时不能提交完成。保存完成后回到 Codex 说“标完了”，不必寻找或上传文件。再次修改并保存会取消先前的完成状态；纯浏览其他题目不会取消完成。

页面不调用模型，不预填语义判断，不改变本人同意范围。敏感类别只表示该信息不应自动进入记忆，不等于允许向外部模型发送。C1 仍是单人 Codex 预实验，不能替代正式六样本或两位独立标注。

## 启动与恢复

在仓库根目录运行，下次启动使用同一输出文件即可恢复：

```powershell
.\scripts\spike.ps1 annotate -preview D:\app\MemorySpike\private\codex-preview-20261013-v2\preview.json -out D:\app\MemorySpike\private\codex-preview-20261013-v2\annotation-review.json -port 8787
```

服务只监听 `127.0.0.1`。同一输出文件只运行一个服务实例；端口冲突时不会结束其他程序。程序或电脑重启后需要重新启动服务，已保存文件不受影响。所有资源随 Go 程序内嵌，没有 CDN、远程字体或运行时前端依赖。

当前电脑已构建 `D:\app\MemorySpike\bin\memory-annotator.exe`，桌面“记忆标注”快捷方式运行 `scripts/open-annotation.ps1`，自动启动隐藏的本机服务并打开浏览器。已有匹配样本的服务会复用。源码变化后应先停止自己启动的服务，在 `scripts/memory_spike` 执行 `go build -o D:\app\MemorySpike\bin\memory-annotator.exe annotate.go` 更新内嵌页面，再打开快捷方式。其他机器可用脚本的 `-Preview`、`-Binary`、`-Port` 参数指定路径。

## 读取结果

当前私人文件：`D:\app\MemorySpike\private\codex-preview-20261013-v2\annotation-review.json`，首次保存时创建。不要把它加入 Git。

- `marks`：消息 ID 到逐题选择和事实的映射；`skip` 明确无个人事实，`uncertain` 待复核，`marked` 有事实。缺少项代表没有审阅。
- `annotation`：与既有 `spike.Annotation` 相同的对象，含 `sample_id`、`sample_sha256`、`annotator`、`complete`、`entries`。后续读取该字段即可；尚未完成时不能作为金标使用。
- `revision`、`current`、`saved_at`：用于多页面版本冲突检查与恢复。服务从逐题原始标记重建金标 ID，事实内容、类别、证据和稳定性保留人工输入。

一份文件同时包含进度与金标，避免保存一半时留下过时的“已完成”金标。保存先写同目录临时文件并同步，再原子替换；失败不覆盖旧文件。接口校验 Host、Origin、随机令牌、请求大小和版本号。它不提供私人目录下载接口。

## 验证

自动测试覆盖草稿、完成门槛、未知证据、样本摘要篡改、重复保存、重启恢复、旧版本冲突、非法来源与令牌。浏览器使用完全独立的虚构两题样本验证填写、保存、漏题拦截、完成提交、刷新恢复与划选原文；真实样本不代填。

已检查桌面和 390px 手机宽度下的页面。桌面快捷方式已创建，启动脚本通过语法检查；自动审批拦截了停止真实服务并通过快捷方式重启的验收操作，因此冷启动快捷方式仍未实测。当前 `8787` 服务已启动，并核实为 108 条真实输入、0 条标记。

设计采用低干扰白底与单一青绿色，原话是主阅读区，侧栏只显示进度与回顾入口。交互通过选中状态和进度条短过渡反馈，遵循系统减少动画设置；保存期间保留固定状态区域，避免闪现“保存中”。
