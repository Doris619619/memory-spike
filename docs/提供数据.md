# 提供你自己的聊天

你本人可以提供一份真实样本。先准备自己同意用于本次模型抽取实验的聊天，不把其他人的账号数据混入。

若学校网站暂时找不到导出入口，可以先用你本人授权的 Codex 本地记录做预实验。新增工具会按来源和发起者筛选文字、去重、遮盖常见凭据，生成供你核对的文件，详见 [Codex 本地取样](CODEX_LOCAL_PREVIEW.md)。Codex 的 C1 样本与学校正式矩阵分开，不证明学校数据库取样正确。

1. 登录学校 AI 网站，进入“会话管理”（当前代码路径 `/conversations`）。
2. 选择愿意参与实验的普通聊天，选择 **导出 → JSON**。不要使用 Markdown 导出或先让模型总结。
3. 保存到 `D:\app\MemorySpike\private\incoming`，告诉代理文件名，并明确说明同意这些聊天用于本次取样、模型调用及人工评估。
4. 不必在此聊天粘贴原文，也不要把原文放到本仓库。单个样本只能代表一位用户，不能把同一人拆成 U1/U2/U3/U6 来冒充四份独立真实样本。

这些入口来自已读取的 UI 代码，不是本次线上浏览器验收。若你的页面不同，先确认页面版本。

**不要仅按会话创建日期导出“最近 30 天”。** 旧会话可能有最近的新消息。正式取样先按会话 `updated_at` 筛选，再按消息 `content.created_at` 判断时间窗。若导出被条数上限截断，也要保留提示说明。

## 网站 JSON 不一定足够

导出文件可用于接收和结构检查，但前端 `getHistoryItem` 的版本可能没有 `source`、`parent_session_id` 等字段。正式方案需要它们排除微信、Project、子任务与校园聊天。不能把缺失值直接当作 `web` 或 `null`。

先运行：

```powershell
.\scripts\spike.ps1 inspect -file 'D:\app\MemorySpike\private\incoming\你的导出文件.json'
```

工具只报告结构与缺失字段，不输出正文，不发送给模型。结构齐全后仍需核对消息树、日期和取样完整性；目前没有声称“任意网站导出可一键转换为正式样本”。

严格方案的正式采集入口是 `collect.go`，通过获得授权的只读 SQL Server 连接按本人 owner 筛选。若网站导出缺字段，由有权维护 Chat 数据的人提供所需的最小元数据或只读取样协助，不能让你猜字段。

## 四份真实样本与人工标注

| 标签 | 要求 |
| --- | --- |
| U1 | 轻度用户：<10 会话、<100 条用户消息 |
| U2 | 中度用户：20–30 会话，混合主题；两人独立标注 |
| U3 | 重度用户：>50 会话、>500 条消息，验证取样上限 |
| U6 | 有明确语言、格式、称呼偏好；两人独立标注 |

你属于哪一类，在检查获准数据后再定，不预先给你贴 U2/U6 标签。U4/U5 可以合成，不需要为敏感场景收集真实秘密。

原文、owner、金标、逐条评分和 raw 输出留在仓库外。评估结束后删除样本转储；若保留评分表且含块文本，也只能在私人目录。运行 `manifest.json` 和 raw 响应同样可能包含原文，属于需要清理的实验副本。清理前明确具体路径，不自动删除唯一的数据来源。
